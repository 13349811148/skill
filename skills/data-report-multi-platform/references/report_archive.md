# 固定保存与按月累计

默认目录：`运营数据库/数据报表输出`。只有用户明确要求时才改变目标路径。

- 拼多多商品：`商品日报_拼多多.xlsx`，子表 `2026-10`、`2026-11` 等。天猫单独使用 `商品日报_天猫.xlsx`，避免混平台计算。
- 店铺：`店铺日报_2026-10.xlsx`、`店铺日报_2026-11.xlsx` 等，每个月固定一个文件，内部保留“①平台日报”版式。
- 不按每次运行另建日期范围 XLSX。JSON、日志、预览及导出期间自动清理的临时目录是辅助文件，不是新日报。

## 更新规则

商品以本次明确请求的完整日期范围为替换范围：删除这些日期全部旧销售/空烧行，再写入本次已校验结果，避免旧SKU和已剔除商品残留；零行日期也清除旧记录。月内正常销售在前、空烧在最后，按稳定业务键排序。未请求的日期、其他月份保留。商品明细的业务键含日期、店铺、商品ID、SKU ID和商品SKU；冲突重复行报错，不盲加。

店铺以“日期+平台+店铺”为键替换本次记录，月内其他日和其他店铺保留；已有人工填写的今日动作/异常说明在新值空白时保留。跨月请求自动分别更新每个月的店铺文件，商品则更新同一总工作簿的对应月子表。原始数值与空白语义保持，重新计算客单价、转化率和其他已确认公式。

`scripts/build_report.py` 自动启用累计模式并将请求日期交给计算进程；`report_archive.py` 读取现有 XLSX 作为数据依据，通过 artifact-tool 导出。输出期间加文件锁，在临时文件导出成功后原子替换目标；生成/核对/文件占用失败不得清空原月报。商品总表若包含未知子表、不同表头或人工公式，停止并说明需要核对迁移，不无声覆盖。

## 历史迁移和修订

首次建立固定报表时，可使用 `report_archive.py product --input <已验证product.json> --output <固定商品总表> --date YYYY-MM-DD`（日期可重复），以及 `report_archive.py store --input <已验证store.json> --output <固定报表目录>` 合并既有结果。迁移时同一日期选择用户最终确认的修订版，不能把早期未剔除版覆盖回去。旧交付文件保留，不删除，也不要将整个工作目录反复扫描导入，以免备份/样例/过期修订混入。

重新计算已有修订日期前先查该日的独立日志及用户已确认口径。商品ID排除、指定订单排除、估算及未知字段的处理仍以该日确认内容为准，不能因为换了保存方式恢复已排除数据。日期限定的排除不能扩展到其他日。例如用户仅要求27日剔除时，26日原值必须保留。

月报 JSON 保留日记录的 `_口径说明`；若有剔除/估算，代理须在导入时填写该说明，并在固定月报的独立日志记录对应日期、来源与规则。历史日期不能仅因新后台导出而被自动重算。

带修订说明的日期受保护：普通原始数据生成不能直接覆盖。商品写入时携带 `date_notes`（CLI可用 `--note`），店铺携带 `_口径说明`，表示已实际执行同日修订；不得用说明绕过真实剔除。更新无关日期不受影响。

## WPS

只同步固定商品工作簿，不上传店铺月报。跟踪同一个商品总工作簿的在线地址；有旧成功链接时使用该文档的更新/上传新版本入口，核对文件身份后更新同一在线文档，不每次再创建一份。不要修改其他在线表格。链接失效或WPS界面无安全可用的替换入口时说明阻塞，保留本地新内容与待更新状态，不擅自删除旧文档。登录交用户操作。固定工作簿内容变更后，旧链接只能作为目标地址，不能当作新内容已上传的证据。
